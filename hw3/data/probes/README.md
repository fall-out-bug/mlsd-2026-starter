# Маленькая история для локальной разработки

`temporal-base.csv.gz` и `temporal-base-request.json` — независимый пример
формата входа. Его SHA-256 зафиксирован в запросе. Полные ожидаемые строки
в `temporal-base-expected.json` служат локальному checker; decimal-значения
записаны строками, чтобы проверка не переходила на float. Набор не содержит
полную историю и не предназначен для выбора модели.

На трёх датах запроса пример должен позволить проверить следующее:

| Сценарий | Наблюдаемое свойство |
| --- | --- |
| Полуоткрытая граница | Заказ `B1` входит в признаки train, `B2` — в его будущую метку. |
| Правая граница метки | Событие `E2` ровно в конце горизонта не делает метку `label_end` положительной. |
| Future-only клиент | `future_only` отсутствует в train и может появиться только после события в истории. |
| Деньги | Для `half` в train: `order_count=2`, `total_amount=2.010000`, `average_order_amount=1.00`. |
| Повтор товарной строки | Для `duplicate` в train: один заказ и `total_amount=2.000000`. |
| Исключения | Отмена, нулевые quantity/price и пустой customer_id не создают допустимого клиента. |

Пустое описание товара и многострочное описание остаются допустимыми. В каждой
части этого запроса есть и строки, и хотя бы один положительный пример. Эти
ожидания — проверяемые свойства контракта; алгоритм их получения вы реализуете
сами.
