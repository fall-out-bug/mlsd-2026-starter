# Проверка технического пакета HW2

03.10.2026, Linux ARM64 (DGX Spark), отдельный Compose-проект `mlsd_hw2_qualification`. Проверка локальная; серверная приёмка и публикация задания не выполнялись.

## Наблюдавшиеся результаты

- Собраны контейнер pipeline (Python 3.12, Java 17, Airflow 2.10.5, PySpark 3.5.4, PyArrow 19.0.0) и MinIO из закреплённого исходника.
- Незаполненная функция студента завершает шаг Airflow ошибкой NotImplementedError; `check.sh` возвращает ненулевой код.
- С отдельной преподавательской реализацией выполнены два последовательных запуска реального DAG. По всему входу получено 345 клиентских агрегатов. Независимый расчёт по CSV совпал со всеми значениями в локальном Parquet, Parquet из MinIO и Redis; повтор не изменил результат.
- Пять unit-проверок прошли: заказ/товарная строка и пропуски; half-even; отсутствующие/лишние/неверные результаты; Parquet с non-nullable счётчиком и повтор клиента; запрет float для денежных полей.
- Намеренно изменённый денежный агрегат в Redis обнаружен проверкой. После восстановления значения полный набор снова проверен.
- SHA-256 входа совпал с манифестом: `e0f37d411cffb5da00fa6dc88a9983d118a8c20bb273096bc84d7f952697f818`.

Преподавательская реализация не входит в стартовый набор. Публичная функция остаётся незаполненной: PASS нельзя ожидать до выполнения студентом работы.

## Воспроизведение

Локальная проверка после выполнения работы: `sh hw2/check.sh`.

Проверки самого проверяющего кода:

```sh
cd hw2
export LOCAL_UID="$(id -u)" LOCAL_GID="$(id -g)"
docker compose run --no-deps --rm --build pipeline python -m unittest discover -s tests -v
```

Полный успешный путь проверялся отдельной преподавательской реализацией с подменой только `customer_features.py` в контейнере. Это техническая репетиция, не прохождение студентом и не проверка удобства работы на его машине.

## Источники и ограничения

Airflow установлен с официальными [constraints для 2.10.5 / Python 3.12](https://github.com/apache/airflow/tree/constraints-2.10.5); снимок constraints включён в комплект. Последовательность запуска использует [Airflow dags test](https://airflow.apache.org/docs/apache-airflow/2.10.5/core-concepts/debug.html).

Старые контейнерные образы MinIO при проверке недоступны. Вместо них используется сборка внутри Docker из [RELEASE.2025-09-07T16-13-09Z](https://github.com/minio/minio/tree/RELEASE.2025-09-07T16-13-09Z), с проверкой SHA-256 архива. [Официальный репозиторий](https://github.com/minio/minio) сообщает о распространении community-версии как исходного кода и отсутствии дальнейшей поддержки. В пакете это изолированный учебный сервис без опубликованных портов.

Docker-образы закреплены дайджестами; сборка Java использует пакет Debian, поэтому побайтовая воспроизводимость образа не заявляется. AMD64/WSL, macOS, режим без сети и серверная проверка не проверялись. Первый запуск требует сети для сборки и загрузки зависимостей.
