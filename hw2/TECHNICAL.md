# HW2: техническая памятка

## Файлы проекта

Пример структуры реализации. Эти файлы создайте самостоятельно:

```text
hw2/
├── compose.yaml
├── airflow/
│   ├── Dockerfile
│   ├── requirements.txt
│   └── dags/online_retail_features.py
└── spark/
    ├── Dockerfile
    ├── requirements.txt
    └── jobs/customer_features.py
```

Можно добавлять модули и вспомогательные файлы. `run.sh` не обязателен.

## Версии

Используйте образы и библиотеки из [versions.json](versions.json): Airflow 2.10.5, Spark/PySpark 3.5.4, Python 3.12, Java 17, SeaweedFS 4.48, Redis 7.4.2, PostgreSQL 16.6.

Внешние образы закрепляйте по дайджесту. Для `postgres`, `redis` и `seaweedfs` используйте предоставленные образы. Для Airflow и Spark нужны собственные Dockerfiles.

Для установки Airflow используйте [официальные constraints для Airflow 2.10.5 и Python 3.12](https://raw.githubusercontent.com/apache/airflow/constraints-2.10.5/constraints-3.12.txt). Сохраните `apache-airflow==2.10.5` в требованиях, чтобы pip не изменил версию Airflow. Собственные зависимости закрепите версиями. Библиотеки Spark для чтения и записи S3 установите при сборке образа. Незакреплённые библиотеки во время обработки скачивать нельзя.

## Сервисы Compose

| Обязательное имя | Назначение и порты внутри контейнера |
|---|---|
| `postgres` | База метаданных Airflow |
| `airflow-init` | Миграция метаданных и создание локальной учётной записи; завершается успешно |
| `airflow-webserver` | Веб-интерфейс и API Airflow, порт 8080 |
| `airflow-scheduler` | Планирование и выполнение задач DAG |
| `spark-master` | Spark master, порт 7077; веб-интерфейс, порт 8080 |
| `spark-worker` | Минимум один зарегистрированный Spark worker |
| `seaweedfs` | S3-совместимое хранилище, порт 8333 |
| `redis` | Хранилище признаков, порт 6379 |

Дополнительные сервисы разрешены. Для Airflow подходит LocalExecutor с PostgreSQL. Celery worker, broker и Flower необязательны. Рекомендуемый `parallelism=2` ограничивает число процессов и расход памяти.

На сервере весь проект получает **4 vCPU и 8 GiB памяти**. Сборка и проверка ограничены **45 минутами**. Рассчитывайте настройки сервисов и число Spark executors на эти ресурсы.

Подключите основные компоненты к стандартной сети `default` проекта. Для связи между контейнерами используйте имена сервисов. Обязательные сервисы должны запускаться без выбора profiles. Не задавайте `container_name`, чтобы несколько Compose-проектов могли запускаться параллельно.

Файлы, каталоги сборки и bind mounts должны находиться внутри `hw2/`. Постоянные данные храните в именованных volumes текущего проекта. Внешние volumes и networks, привилегированные контейнеры, устройства хоста, Docker socket и доступ к пространствам процессов и сети хоста не допускаются.

У обязательных сервисов, кроме завершающегося `airflow-init`, настройте healthcheck. Airflow запускается после готовности PostgreSQL и успешного завершения `airflow-init`; для последнего используйте `condition: service_completed_successfully`. Установка библиотек, миграция базы и создание подключений должны выполняться при сборке и запуске, без ручных действий внутри контейнеров.

## Параметры подключения

По умолчанию используйте:

- Airflow API: пользователь `airflow`, пароль `airflow`, Basic authentication.
- S3: access key `hw2-local`, secret key `hw2-local-only`, region `us-east-1`.
- Redis: без пароля внутри сети проекта.

Изменённые локальные параметры передавайте через окружение и опишите в README.

API Airflow внутри проекта: `http://airflow-webserver:8080/api/v1`. Для доступа к веб-интерфейсу с хоста публикуйте его порт на `127.0.0.1`; номер порта можно менять через окружение. Другим сервисам порты на хосте не нужны.

## DAG и Spark

DAG ID — `online_retail_features`, `schedule=None`, catchup отключён. После запуска среды DAG должен быть включён и доступен для ручного запуска. Обязательные задачи описаны в [условии](README.md). Можно добавлять вспомогательные задачи. Ошибка этапа должна завершать DAG ошибкой.

Spark-программа выполняется в кластере master/worker. У driver и workers должна быть одинаковая версия Python. При самостоятельной сборке Spark настройте `SPARK_HOME` и запускайте компоненты средствами дистрибутива. Worker должен уметь запускать executors.

Имя Spark application — `online_retail_features`. Каждый запуск DAG создаёт отдельное приложение. Весь расчёт выполняйте средствами Spark; `toPandas` и расчёт вместо Spark запрещены.

## Запуск и локальная проверка

Нужны Docker с Compose v2 и Python 3.10+ для команды проверки. Проверяющая программа с зависимостями запускается в контейнере; дополнительные Python-библиотеки на компьютере устанавливать не нужно. Первый запуск требует сети для сборки образов и установки зависимостей.

Из каталога `hw2/` запустите среду:

```sh
docker compose up --build --wait
```

Откройте веб-интерфейс Airflow и запустите DAG кнопкой Trigger DAG.

Из корня репозитория выполните проверку:

```sh
sh check.sh HW2
```

Проверка создаёт отдельный Compose-проект и после завершения удаляет его. Логи сохраняются в `hw2/output/`.

Остановите свою среду из `hw2/`:

```sh
docker compose down
```
