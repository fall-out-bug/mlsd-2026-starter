# HW2: данные и агрегаты по клиенту

Подготовьте признаки из небольшого среза Online Retail II. Один запуск должен прочитать данные, отобрать покупки, посчитать агрегаты, сохранить Parquet в SeaweedFS (S3) и значения в Redis. Другой человек должен суметь повторить этот запуск по вашей инструкции.

## Что уже предоставлено

Compose запускает SeaweedFS (S3) и Redis; контейнер pipeline содержит Airflow, Spark и зависимости. Airflow выполняет три шага: подготовить вход → посчитать признаки → опубликовать результат. Spark работает локально с двумя потоками; отдельный кластер не нужен.

Вход `data/sample.csv` уже включён: 11 116 строк, около 1 МБ. Не заменяйте его и `SHA256SUMS`. Происхождение, лицензия CC BY 4.0 и ограничения описаны в [data/README.md](data/README.md). Это учебная выборка заказов, а не полная история клиентов. Временные окна, будущие метки и обучение модели в HW2 не входят.

## Ваша часть

Реализуйте функцию `customer_features(rows)` в [customer_features.py](customer_features.py), используя операции Spark DataFrame. Инфраструктурный код и проверку менять не требуется. Входные колонки читаются как строки; нужные числовые поля приведите к типам.

Для расчёта оставьте строки, у которых:

- `customer_id` не пустой;
- `invoice_id` не начинается с `C` без учёта регистра;
- `quantity > 0`;
- `unit_price > 0`.

Пропуск `description` не мешает этим признакам. Не объединяйте отсутствующие идентификаторы в одного клиента. Не удаляйте одинаковые строки автоматически: принадлежность одному заказу не делает товарную строку дублем.

Верните по одной строке на каждого клиента, у которого остались выбранные покупки, в таком порядке:

| Поле | Spark type | Значение |
|---|---|---|
| `customer_id` | string | Идентификатор из входа |
| `order_count` | long | Число **различных** `invoice_id` |
| `total_amount` | decimal(20,6) | Сумма `quantity × unit_price` |
| `average_order_amount` | decimal(20,2) | `total_amount / order_count` |

Для цены используйте decimal(20,6), а не float/double. Средний чек округляйте до двух знаков методом half even: точная середина округляется к ближайшей чётной цифре. В Spark для этого есть `bround`. Например, 1.005 → 1.00 и 1.015 → 1.02. Исходная цена имеет не более шести знаков после запятой; сумму сохраните с шестью знаками. `quantity` можно привести к long; количество различных заказов Spark возвращает как long.

Считайте по всему предоставленному срезу. Три агрегата характеризуют выбранные положительные покупки; это не бухгалтерский итог с возвратами.

## Пример

Условные строки:

| Invoice | Клиент | Quantity | Unit price |
|---|---|---:|---:|
| A | U | 2 | 3 |
| A | U | 1 | 4 |
| B | U | 1 | 3 |
| C-A | U | -1 | 3 |
| D | пусто | 1 | 5 |
| E | V | 1 | 0 |

После отбора остаются три строки клиента U: **два заказа**, сумма **13.000000**, средний чек **6.50**. В выходе нет клиента V. Если description в строке B пустое, она всё равно учитывается.

## Запуск и локальная проверка

Нужны Docker Engine/Desktop с Compose v2 и WSL/Linux/macOS с `sh`. До запуска проверьте `docker version` и `docker compose version`. На диске желательно 5 ГБ свободного места; Docker должен иметь доступ как минимум к 4 ГБ RAM. Первый запуск скачивает готовые образы SeaweedFS и Redis; сборка pipeline скачивает Java и Python-зависимости. Это может занять несколько минут; последующие сборки используют кеш. Версия и digest SeaweedFS закреплены в Compose.

Из корня вашего репозитория:

```sh
sh hw2/check.sh
```

До реализации функция выдаёт `NotImplementedError`, а проверка — FAIL. Это ожидаемое состояние заготовки.

После реализации проверка дважды запускает настоящий Airflow DAG, читает локальный Parquet, скачивает Parquet из SeaweedFS (S3) и читает Redis. Она сверяет набор клиентов и все три значения с исходным CSV. Второй запуск должен вернуть те же агрегаты, а не удвоить суммы.

После PASS в `hw2/output/` находятся входная копия, каталог `features.parquet/` и `check-result.json`. Spark пишет Parquet как каталог из частей, а не обязательно один файл. SeaweedFS (S3) хранит `hw2/input/sample.csv` и `hw2/features/*.parquet`. Redis хранит ключи `hw2:customer:<customer_id>` с JSON: order_count — число, денежные значения — строки с фиксированной точностью. Публикация и чтение уже реализованы в заготовке.

Для отдельного запуска без проверки:

```sh
cd hw2
mkdir -p output
export LOCAL_UID="$(id -u)" LOCAL_GID="$(id -g)"
docker compose up -d s3 redis
docker compose run --rm --build pipeline
```

Контейнеры SeaweedFS (S3) и Redis продолжают работать после проверки. Порты на хост не публикуются. Когда закончите, остановите только Compose-проект этой работы:

```sh
cd hw2
docker compose down
```

В этой заготовке данные сервисов временные: down удаляет их вместе с контейнерами. Локальный Parquet в output остаётся; новый запуск восстановит сервисные копии из входного файла. Не используйте глобальные команды очистки Docker.

## Что подготовить к сдаче

Реализацию `customer_features.py` и короткое пояснение в своём README: какие строки исключаются, чем число заказов отличается от числа строк, где лежит результат и как его повторить. Не коммитьте `output/`.

**Пакет подготовлен к публикации 5 октября после лекции 3.** Пока преподаватель не объявил выпуск, приёмка HW2 не считается открытой. Как добавить `hw2/` в существующий репозиторий, описано в [UPDATE.md](UPDATE.md).

После объявления сдавайте в зарегистрированном репозитории, в ветке `main`, отдельным коммитом с единственным маркером последней строкой сообщения:

```sh
git add hw2/customer_features.py README.md
git commit -m 'MLSD-HW: HW2'
git push origin main
```

Сервер проверяет принятый SHA и самостоятельно запускает закреплённую инфраструктуру с вашей `hw2/customer_features.py`. Он дважды читает настоящий Parquet/S3/Redis и сверяет агрегаты с исходными данными. Изменения локальной проверки, DAG, Compose и файла PASS не меняют серверную оценку. Локальный PASS помогает проверить решение; принятая сервером сдача и серверный результат отображаются через систему курса. Не используйте маркер HW1 для HW2.

Плановые сроки по программе курса (2026, 18:00 МСК): выдача 5 октября; конец раннего бонуса строго до 12 октября; мягкий срок 19 октября; жёсткий 26 октября. Официальное условие и правила сдачи публикуются преподавателем.
