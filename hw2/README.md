# Домашняя работа 2: подготовка клиентских признаков

## Цель задания

Собрать проект на Docker Compose, в котором Airflow управляет обработкой данных, Spark рассчитывает признаки по клиентам, SeaweedFS хранит CSV и Parquet через S3 API, а Redis — готовые признаки.

Вы самостоятельно пишете конфигурацию Compose, Dockerfiles, DAG, Spark-программу и код сохранения результата.

## Данные и версии

В `data/sample.csv` находятся 11 116 строк Online Retail II. Используйте этот файл; полный архив UCI скачивать не нужно. `SHA256SUMS` содержит контрольную сумму исходного CSV для проверки его целостности. Сохраните исходный файл и `SHA256SUMS` без изменений; обработку данных реализуйте отдельно в Spark-программе. Происхождение данных и лицензия описаны в [data/README.md](data/README.md). Интернет нужен при сборке образов и установке зависимостей; затем обработка использует предоставленные данные.

Используйте версии и образы, закреплённые по digest в [versions.json](versions.json): Airflow 2.10.5, Spark/PySpark 3.5.4, Python 3.12, Java 17, SeaweedFS 4.48, Redis 7.4.2 и PostgreSQL 16.6 для метаданных Airflow.

Для Python-зависимостей Airflow предоставлен официальный `constraints.txt`. При установке библиотек оставляйте `apache-airflow==2.10.5` в требованиях, чтобы pip не изменил версию Airflow. Собственные зависимости также закрепите версиями. Зависимости Spark для чтения и записи S3 подготовьте при сборке образа; не скачивайте незакреплённые библиотеки во время обработки.

## Задача

### 1. Настройте Docker Compose

В проекте должны быть сервисы с такими именами:

| Сервис | Назначение |
|---|---|
| `postgres` | База метаданных Airflow |
| `airflow-init` | Миграция метаданных и создание локальной учётной записи; завершается успешно |
| `airflow-webserver` | Веб-интерфейс и API Airflow на внутреннем порту 8080 |
| `airflow-scheduler` | Планирование и выполнение задач DAG |
| `spark-master` | Spark master на порту 7077; внутренний веб-интерфейс на порту 8080 |
| `spark-worker` | Минимум один зарегистрированный Spark worker |
| `seaweedfs` | S3-совместимое хранилище на внутреннем порту 8333 |
| `redis` | Хранилище признаков на внутреннем порту 6379 |

Дополнительные сервисы разрешены. Для Airflow можно использовать LocalExecutor с PostgreSQL; Celery worker, broker и Flower не обязательны. Для этой выборки достаточно `parallelism=2`, чтобы ограничить число процессов и расход памяти. Не выделяйте десятки Spark executors: на сервере весь проект получает **4 vCPU и 8 GiB памяти**, а сборка и проверка ограничены **45 минутами**.

Подключите основные компоненты к стандартной сети `default` проекта. Для подключений между контейнерами используйте имена сервисов. `localhost` внутри контейнера указывает на него самого. Не задавайте `container_name`, чтобы Compose мог запускать несколько проектов параллельно.

Файлы и bind mounts должны находиться внутри `hw2/`. Постоянные данные храните в именованных volumes своего Compose-проекта.

Настройте healthcheck и зависимости запуска: Airflow должен стартовать после готовности PostgreSQL и успешного завершения `airflow-init`. После запуска среды не должны требоваться ручная установка библиотек, миграция базы или создание подключений.

Используйте следующие параметры локального учебного доступа по умолчанию:

- Airflow API: пользователь `airflow`, пароль `airflow`, Basic authentication.
- S3: access key `hw2-local`, secret key `hw2-local-only`, region `us-east-1`.
- Redis: без пароля внутри сети проекта.

Если меняете эти параметры локально, передавайте их через окружение и опишите настройки в README. Персональные токены и учётные записи не нужны.

### 2. Напишите DAG и Spark-программу

DAG ID — `online_retail_features`, `schedule=None`, catchup отключён. После старта среды DAG должен быть доступен, включён и готов к ручному запуску. API Airflow внутри проекта: `http://airflow-webserver:8080/api/v1`.

Обязательные задачи выполняются в таком порядке:

```text
get_dataset → put_dataset → features_engineering → load_features
```

| Задача | Что она делает |
|---|---|
| `get_dataset` | Читает предоставленный `sample.csv` и проверяет хеш из `SHA256SUMS` |
| `put_dataset` | Записывает исходные байты в S3: bucket `hw2`, key `input/sample.csv` |
| `features_engineering` | Запускает вашу Spark-программу: она читает CSV из S3, рассчитывает признаки и пишет Parquet в `hw2/features/` |
| `load_features` | Читает сохранённый Parquet и записывает признаки в Redis |

Можно добавлять вспомогательные задачи. Каждый обязательный этап должен выполнять указанную работу; заглушки не допускаются. Ошибка этапа должна завершать DAG ошибкой.

Spark-программа должна выполняться в кластере master/worker. У driver и workers должна быть одинаковая версия Python. Если собираете Spark самостоятельно, настройте `SPARK_HOME` и запускайте компоненты штатными средствами дистрибутива. Проверьте, что worker может запускать executor: одного доступного веб-интерфейса master недостаточно.

Имя Spark application — `online_retail_features`. Для каждого запуска DAG создавайте отдельное приложение. Весь расчёт выполняйте средствами Spark; `toPandas` и расчёт вместо Spark запрещены.

### 3. Рассчитайте признаки

Входной CSV содержит следующие поля:

| Поле | Значение |
|---|---|
| `invoice_id` | Номер заказа; префикс `C` обозначает отмену |
| `stock_code` | Код товара |
| `description` | Описание товара; может отсутствовать |
| `quantity` | Количество единиц товара, целое число со знаком |
| `invoice_at` | Время заказа в формате ISO 8601 без часового пояса |
| `unit_price` | Цена единицы товара, до шести знаков после запятой |
| `customer_id` | Идентификатор клиента; может отсутствовать |
| `country` | Страна |

Для расчёта оставьте строки, у которых:

- `customer_id` не пустой;
- `invoice_id` не начинается с `C` без учёта регистра;
- `quantity > 0`;
- `unit_price > 0`.

Пустой `description` не исключает покупку. Не удаляйте одинаковые товарные строки автоматически. Считайте по всему предоставленному срезу; результат описывает выбранные покупки этой учебной выборки, а не полную историю клиента.

## Результат

В Parquet должна быть одна строка на каждого оставшегося клиента, без NULL и повторов клиентов. Поля идут в таком порядке:

| Поле | Тип Spark | Значение |
|---|---|---|
| `customer_id` | string | Идентификатор клиента |
| `order_count` | long | Число различных `invoice_id` |
| `total_amount` | decimal(20,6) | Сумма `quantity × unit_price` |
| `average_order_amount` | decimal(20,2) | `total_amount / order_count`, округление half even |

Для цены используйте `decimal(20,6)`. При округлении half even точная середина округляется к ближайшей чётной цифре. В Spark для этого подходит `bround`: 1.005 → 1.00, 1.015 → 1.02.

Например, две товарные строки с одинаковым `invoice_id` — это один заказ. Если их суммы равны 6 и 4, а сумма ещё одного заказа равна 3, результат: `order_count=2`, `total_amount=13.000000`, `average_order_amount=6.50`.

В Redis используйте ключ `hw2:customer:<customer_id>`. Значение — JSON: `order_count` хранится числом, `total_amount` и `average_order_amount` — строками с фиксированной точностью. Поле `customer_id` внутри JSON допустимо, но должно совпадать с идентификатором в ключе.

Повторный запуск на том же входе должен возвращать тот же результат. Суммы не накапливаются; старые части Parquet и устаревшие ключи этой работы не остаются в результате.

## Запуск и локальная проверка

Для локальной проверки нужен Python 3.10+; дополнительные Python-библиотеки на компьютере устанавливать не нужно. Проверяющая программа с зависимостями запускается в отдельном контейнере.

Запустите собственную среду из каталога `hw2/`:

```sh
docker compose up --build --wait
```

Откройте веб-интерфейс Airflow и запустите DAG кнопкой Trigger DAG. Для доступа с хоста публикуйте порт веб-интерфейса на `127.0.0.1`; номер порта можно менять через окружение. Другим сервисам порты на хосте не нужны.

Из корня репозитория выполните локальную проверку:

```sh
python3 hw2/check.py
```

Она создаёт отдельный Compose-проект, запускает ваш DAG дважды через API, читает S3 и Redis и сверяет результат. После проверки удаляется только созданный ею проект. Логи каждого прогона сохраняются в `hw2/output/`. Локальный `PASS` означает успешную проверку на вашей машине; оценку выставляет сервер курса.

Остановить собственную среду из `hw2/`:

```sh
docker compose down
```

## Требования и автоматическая проверка

Учебная работа — полный проект: Compose, образы, DAG, расчёт средствами Spark, сохранение результата и инструкция воспроизведения. В корневом README опишите компоненты, запуск, расчёт, места хранения результата и повторный запуск.

Серверная проверка:

- собирает ваш проект и проверяет сервисы;
- запускает DAG дважды и проверяет два отдельных Spark application;
- читает фактический CSV и Parquet из S3, JSON из Redis;
- сравнивает всех клиентов и агрегаты с независимым расчётом;
- проверяет одинаковый результат повторных запусков.
