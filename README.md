# Домашняя работа 1: контейнер с проверкой здоровья

В этой работе нужно собрать небольшой сервис в Docker. Он должен отвечать на
запрос `GET /health` JSON-объектом, в котором есть поле `"status":"ok"`.
Другие поля в ответе допустимы. Язык и фреймворк выбираете вы.

## Как начать

Шаблон private repository будет опубликован отдельно. Когда преподаватель даст
ссылку на GitHub template, создайте из него новый private repository, затем
склонируйте его и перейдите в каталог проекта:

```sh
git clone <ссылка-на-ваш-private-repository>
cd <каталог-репозитория>
```

Не используйте fork репозитория курса. Работайте в ветке `main`.

Нужны Git, Docker Desktop или Docker Engine с запущенным daemon, а также
стандартные команды WSL/Linux: `sh`, `curl`, `awk`, `grep`, `date`, `rm` и
`timeout`. Проверьте Docker:

```sh
docker version
```

В выводе должны быть разделы Client и Server.

## Что должно быть в репозитории

Добавьте в корень repository:

- `Dockerfile`. Каждая строка `FROM`, кроме `FROM scratch`, должна указывать
  образ с sha256 digest: `image@sha256:<64 символа>`.
- Один файл закреплённых зависимостей: `uv.lock`, `poetry.lock`,
  `Pipfile.lock`, `requirements.lock`, `package-lock.json`,
  `npm-shrinkwrap.json`, `pnpm-lock.yaml`, `yarn.lock`, `Cargo.lock` или
  `go.sum`.
- Свой `README.md` с обычными командами сборки и запуска. В команде сборки
  context должен быть `.`, а в команде запуска должен быть порт `8080`.
- Сервис с `GET /health`. Он должен ответить за две секунды JSON-объектом с
  полем `"status":"ok"`.

Например, в вашем README могут быть такие команды:

```sh
docker build --tag hw1 .
docker run --publish 8080:8080 hw1
```

Docker Compose можно использовать дополнительно, но он не заменяет Dockerfile
и эти две команды.

## Локальная проверка

Из корня repository выполните:

```sh
sh ./check.sh
```

Скрипт проверит обязательные файлы, соберёт container, запустит его, обратится
к `/health` и удалит созданные этим запуском container и image. `PASS` означает
только, что локальная проверка прошла. Не запускайте скрипт в чужом
недоверенном repository: Docker build выполняет его код локально.

Если видите `FAIL`, прочитайте сообщение, исправьте указанную проблему и снова
запустите `sh ./check.sh`.

## Commit и push

После local `PASS` сохраните работу в Git и отправьте ветку:

```sh
git add .
git commit -m 'MLSD-HW: HW1'
git push origin main
```

Этот commit помечает работу как HW1. Локальный скрипт marker не проверяет,
потому что он проверяется на стороне курса после push.

Подключение repository к системе курса пока не опубликовано. Позже появится
отдельная инструкция: установка GitHub App, вход через GitHub, выбор
repository и привязка Telegram. До этой инструкции local `PASS` и push не
подтверждают приём работы или оценку.
