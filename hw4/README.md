# Домашняя работа 4. Онлайн-фичестор и сервис применения модели

HW4 продолжает проект HW3. Данные, `postgres`, `airflow`, `spark`, `mlflow`
и `seaweedfs` сохраняются; модель уже обучена и сохранена. Теперь её нужно
применять как сервис: принимать пару «клиент + дата», брать восемь признаков
из онлайн-хранилища и отвечать вероятностью выбранной версии модели.

Полное условие — [TECHNICAL.md](TECHNICAL.md). Оно фиксирует сервисы, вход,
признаки, офлайн-путь, модели, активную версию, эндпоинты, ошибки и лимиты.

## Что нужно построить

- `hw4/compose.yaml` с обязательными сервисами: `postgres`, `airflow-init`,
  `airflow-webserver`, `airflow-scheduler`, `spark-master`, `spark-worker`,
  `seaweedfs`, `mlflow`, `redis`, `gateway`, `feature-service`,
  `model-service`, `feature-build`, `feature-loader`.
- `feature-build` — расчёт восьми признаков из истории в Parquet в
  `seaweedfs`.
- `feature-loader` — загрузка признаков в Redis по ключу
  `hw4:features:<client_id>:<as_of>`.
- `gateway` на `8080` — `/health`, `/predict`, `/predict/batch`, `/model`,
  `/admin/activate`.
- `feature-service` на `8081` — выдача вектора признаков.
- `model-service` на `8082` — применение модели из MLflow.
- Две модели в MLflow: `hw4-logistic` и `hw4-boosting`.
- Таблицу `hw4.active_model` в Postgres и восстановление выбора после
  перезапуска.
- `requirements.lock` и `README.md` с запуском и переменными окружения.

Внутренняя структура модулей — на ваше усмотрение. Контракт фиксирует только
наблюдаемое поведение и артефакты.

## Данные для локального запуска

Маленькая история лежит в `hw4/data/history.csv.gz`, запрос — в
`hw4/data/request.json`, ожидаемые признаки — в
`hw4/data/expected_features.json`. Это примеры форматов и границ, а не
канонический набор. Полная история HW3 скачивается по инструкции HW3 и не
хранится в Git.

## Запуск

```bash
cd hw4
docker compose up --build --wait
```

Вход монтируется read-only в `/input` через переменную `HW4_INPUT_DIR`.
`feature-build` и `feature-loader` — одноразовые сервисы; `gateway` стартует
после их успешного завершения.

## Проверка и сдача

```bash
sh check.sh HW4
```

Сдача — ветка `main`, последняя строка сообщения коммита — ровно
`MLSD-HW: HW4`.

HW4 выдаётся 9 ноября 2026. До 16 ноября в 18:00 МСК зачтённая реализация
получает 10 базовых баллов и 3 балла ранней сдачи, затем ранний бонус не
начисляется. Мягкий дедлайн — 23 ноября, жёсткий — 30 ноября (после него
базовая оценка равна нулю).
